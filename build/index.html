01 How I work

  1. I learn a process fast.At the parts dealership, it took one week from my first look at their old ERP to a first demo, and to first real use.
  2. I look for where the time goes.About 95% of the dealership's orders come in by phone. So I worked on the phone call, not on another form.
  3. I change the plan when the facts change.A general LLM gave the right answers but was too slow for a live call (1.5 s per answer). I switched to a smaller decision model that answers in 0.43 s.
  4. I check my own numbers.A list of top parts looked like it covered 71.9% of orders. When I used the customer's actual car instead of the car in the parts data, it was 57.3%. That is the number I report.
  5. I use what is already there.The dealership's ERP only runs in Internet Explorer. I didn't replace it. A bot works inside it through its own scripting interface, and I run the system remotely from Munich.
  6. People make the final call.In my systems, the computer suggests and a person confirms. If the computer is unsure, it leaves the field empty instead of guessing.

Live call-to-quote autofill

2026 · personal project
GitHub ↗

While a repair shop is on the phone, the parts quote fills itself in. The caller says “a fender for the Vera, left… no, the right one”, and the form follows. A general LLM was correct but too slow for this, so I used a decision model. It picks from fixed lists (car, body part, side, damage) and is about 3.5 times faster. It leaves a few more fields for the person, but it says how sure it is, so unsure fields stay empty. Part numbers come from the catalogue, not from the model.

22 staged test calls: 74–75 of 78 values filled, 0 wrong (general LLM: 77 filled, 0 wrong).

Case checker for consumer advice — Verbraucherzentrale Bayern

2026 · Legal Loves Tech hackathon, developer in a team of 3
GitHub ↗

Consumer advisers check contracts and letters by hand, and the result can depend on who is on duty. Our tool reads the same documents and gives a verdict in the categories VZ Bayern asked for, with a template letter and a quote from the document for each reason. If a document is missing, it says which one. A fixed rule engine makes the decision, not a language model, and names stay on the computer.

447 tests pass. Follow-up presentation to VZ Bayern, 10/2026.

Verifiable legal RAG

2026 · personal project
GitHub ↗

Legal AI tools often make things up (17–33% of answers, Stanford RegLab 2025). Here every claim must come with an exact quote, and simple code checks that the quote is really in the source. If it isn't, the claim is marked as failed. No frameworks, so every step can be inspected.

51 offline checks.

LLMs to analyse business models

2025 · Bachelor's thesis, grade 1.3

A command-line tool where a local LLM reads UML and BPMN 2.0 / ARIS models stored as XML and answers questions about them. Large models are split into parts (Map-Collapse-Reduce), and edits asked in plain language are written back as valid XML.
