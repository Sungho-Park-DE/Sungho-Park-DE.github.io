02 How I build

  1. inA phone call or a set of documents
  2. proposeThe model suggests, from fixed lists
  3. decideA rule or a person decides
  4. writeA bot types it into the old system
  5. checkRead back and compare; anything odd goes to a person
  1. The person has the last word.Machine values show up as suggestions; nothing is sent until a person confirms, and what a person typed is never overwritten.
  2. Empty beats wrong.When the model isn't confident, the field stays empty — or an earlier guess is taken back.
  3. Wrap, don't replace.Old systems keep running untouched; a bot drives them through the scripting interface they already have.
  4. Make the dangerous things impossible, not just avoided.Printing, deleting and final confirmation simply aren't on the bot's list of allowed actions.
  5. Don't trust a system's own "saved".After saving, the bot reads the document back and compares it with what was meant; anything unexpected goes to a person.

03 Selected work

Live call-to-quote autofill

2026 · personal project
GitHub ↗

While a repair shop is still on the phone — “a fender for the Vera, no, not left, the right one” — the quote form fills itself in, and the person on the call has the last word. A decision model picks from fixed lists (car, body zone, side, damage), so it can't invent a part; exact part numbers come from the catalogue.

Measured on 22 labelled, staged calls: 74–75 of 78 field values filled, 0 wrong; deciding on partial speech had the draft complete 4–23 s earlier.

Quote automation for a parts dealership

since 08/2026 · service contract
GitHub ↗

A dealership in Korea runs on a legacy ERP built for Internet Explorer and ActiveX. Instead of replacing it, I put a quote web app and a rule-based bot on top: the bot types confirmed quotes into the ERP, reads them back, and stops for a person when anything looks off. No language model at run time. Operated and maintained remotely from Munich.

Production code stays private (customer data); the design and safeguards are published on invented fake systems.

Case checker for consumer advice — Verbraucherzentrale Bayern

2026 · Legal Loves Tech hackathon, developer in a team of 3
GitHub ↗

An adviser gets a case — contract, terms, a price-increase letter, often incomplete — and today reads it by hand; the result depends on who is on duty. The checker reads the same documents and returns a verdict in exactly the categories VZ Bayern asked for, a matching template letter, and the reasons, each with a verbatim quote. If something is missing, it names the document and drafts the request. Names never leave the computer, and no language model makes the decision — a deterministic rule engine does.

Follow-up presentation to VZ Bayern, 10/2026.

Verifiable legal RAG

2026 · personal project
GitHub ↗

Even commercial legal AI tools hallucinate in 17–33% of answers (Stanford RegLab, 2025). Here every claim the model makes must carry a verbatim quote that plain code checks against the source — a made-up claim gets a failing badge instead of a persuasive paragraph. Built without frameworks to keep every moving part inspectable.

LLMs to analyse business models

2025 · Bachelor's thesis, grade 1.3

A command-line tool in which a local LLM reads UML and BPMN 2.0 / ARIS models from XML and answers questions about them — with Map-Collapse-Reduce chunking for models too large for the context, and natural-language edits exported back to valid XML.
